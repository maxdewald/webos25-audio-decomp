RESULT
The recovered audiod chain does NOT derive mix from codec, sound-output mode,
source category, active-input count, game, BT, voice or system sounds. It takes
a validated boolean from a registered Luna method and arbitrates by caller ID.
The count at TVManager +0x2c4/+0x2c8 is mixing-holder IDs, NOT active inputs.

DECISION TABLE (UMI forwarding must also be ready)
true, new ID: add ID, send true.
true, existing ID: no duplicate, send true.
false, ID present, last holder: erase ID, send false.
false, ID present, other holders remain: erase ID, no send, return success.
false, ID absent, holder set empty: send false.
false, ID absent, other holders remain: no send, return success.
No incoming request: no state-to-boolean mapping recovered in this audiod path.

INBOUND
luna://com.webos.service.audio/tv/mixDigitalSoundOutput
Request: {"mix":false,"callerId":"mixer-probe"}; callerId is optional.
Only mix (boolean) and callerId (string) are accepted by the schema.
Omitted/empty callerId uses LSMessageGetApplicationID, then sender service name.
This is caller-facing, not an internal-only method. Actual bus permission and
API support/stability for an arbitrary application remain unverified.

OUTBOUND
luna://com.webos.service.audiooutput/quality/setSettings
{"category":"setMixer","value":{"mix":false,"callerId":"mixer-probe"}}
value is a copy of the original request, not a freshly synthesized object.
Top-level key is category, NOT key. Audiod does not await downstream effect.

COVERAGE AND LIMITS
One recovered setMixer literal constructor; its two direct incoming calls are
both arbitration branches, reached from the registered callback. All .text was
indexed for direct calls and supported PC-relative string loads; no other
absolute pointer to sender/arbitration was found outside dynsym. Computed
indirection and callers in other service binaries are not exhaustively ruled out.
The requested mode/source/game/BT/voice/system-sound truth table cannot be
established from audiod alone. No codec-only conclusion is warranted.
Other holder IDs can suppress false. UMI object +4 and ready byte +0x34 must be
valid. Bus ACL, current holders, lifecycle cleanup, later overwrites and actual
downstream no-mix realization remain unproven. Neighbor owns downstream policy.

BEST NEXT EXPERIMENT (NOT EXECUTED)
With authorization, passively correlate inbound mixDigitalSoundOutput sender IDs
and outbound category:setMixer while changing one ordinary UI state at a time:
speaker/ARC/optical, one/two inputs, game, BT, voice/TTS, system sound. Record
requests, replies, timing and actual active states. A false reply with no outbound
setMixer points to holder arbitration; outbound false with mixed output points
downstream. Do not clear a real service's ID or assume no pre-existing holders.
